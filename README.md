# 은퇴 시니어를 위한 내 자산 AI 네비게이터

퇴직 전후 55~64세 중장년층을 대상으로, 자산·소득·연금을 종합 분석해
"그래서 지금 무엇을 해야 하는가"를 알려주는 금융 의사결정 지원 AI.

## 설계 원칙

> **`core/`는 LLM을 절대 호출하지 않는다.**
> LLM은 (a) 사용자 입력을 구조화하고 (b) 계산 결과를 설명하는 양 끝단에만 존재한다.

금융 서비스에서 숫자를 LLM이 만들면 환각 리스크를 통제할 수 없다.
모든 계산은 `core/`의 순수 파이썬 함수가 담당하고, LLM에는 "제시된 숫자만
인용하고 직접 계산하지 말 것"을 강제한다.

쉬운 규칙을 결정론적 엔진과 몬테카를로가 **공유**하게 해서 두 엔진이 조용히
어긋나는 것을 막는다. 일치 여부는 "변동성 0이면 몬테카를로가 결정론적 결과와
같아야 한다"는 테스트로 강제한다.

## 계산 규약 (발표 대응용)

1. 시뮬레이션은 **퇴직 시점부터** 시작한다. 퇴직 전 축적은 반영하지 않는다(보수적).
2. 투자수익은 **연초 잔액 기준**, 인출은 연말 발생으로 본다.
3. 생활비는 매년 물가상승률만큼 증가. 국민연금은 법정 물가연동 반영.
   기타소득(임대·근로)은 물가에 연동하지 않는다(보수적).
4. 세금은 이자·배당 성격 수익(현금성·채권)에만 부과. 국내주식 양도차익은
   소액주주 비과세 현실을 반영해 과세하지 않는다.
5. 퇴직 연도와 연금 개시 연도는 개월 단위로 안분한다.
6. **세금·건강보험료는 실효세율 근사다. 화면에 "참고용" 고지가 필수다.**
7. 몬테카를로는 자산군 간 상관계수 0, 연도 간 독립, 정규분포를 가정한다.
   실제 시장의 상관과 두꺼운 꼬리를 반영하지 않으므로 꼬리 위험을 과소평가할 수 있다.

가정값의 근거는 전부 `data/assumptions.yaml`의 주석에 있다.

## 기획서에서 의도적으로 벗어난 지점

**리스크 스코어에 지속가능성 상한을 추가했다.** 기획서의 가중치는 단기 항목
(소득공백기 30% + 유동성 25%)에 55%가 몰려 있어, "지금은 현금이 넉넉하지만
69세에 파산이 확실한" 사람에게도 87점이 나온다. 화면에 *양호 87점*과
*만 69세 자산 고갈*이 나란히 뜨면 사용자는 무엇을 믿어야 할지 알 수 없고,
심사에서도 바로 지적받을 지점이다.

가중치 자체는 기획서를 그대로 두되, 시뮬레이션이 파산을 가리키면 종합 점수가
그 사실을 넘어설 수 없게 상한을 뒀다 (75세 이전 고갈 → 40점, 85세 이전 → 60점).
또 `장기소득` 항목은 연금/생활비 비율뿐 아니라 실제 고갈 시점을 함께 반영한다.

가중치를 바꾸는 편이 낫다고 판단되면 `core/risk_score.py`의 `WEIGHTS`와
`_sustainability_cap` 을 함께 조정할 것.

## 검증 기준

기획서 예시 인물(2026년 12월 퇴직, 금융자산 2.2억, 월 생활비 300만,
국민연금 월 150만·2030년 개시)에 대해 엔진이 산출하는 값:

- 소득공백기 **4년**
- 생활비 충당 가능 **6.2년** ← 기획서의 "약 6.2년"과 일치
- 연금 개시 시점 잔액 **1억 1,855만원**
- 금융자산 고갈 **2035년(만 69세)**
- 은퇴 재무 안정도 **40/100 (부족)** — 원점수 87점에 지속가능성 상한 적용

이 숫자들은 `tests/test_demo_regression.py`에 고정되어 있다.
가정값을 바꿔서 깨지면, 테스트를 고치지 말고 **바뀐 숫자가 의도한 것인지 먼저 확인**할 것.

## 데모 페르소나 두 개의 역할

| | DEMO (기획서 예시) | DIVERSIFIED |
|---|---|---|
| 성격 | 단기는 안전, 장기는 파산 | 자산 분산, 계획 지속 가능 |
| 안정도 | 40/100 부족 | 98/100 양호 |
| 시나리오 비교 | 세 안이 동일 (위험 감수 여력 없음) | 고갈 확률 1% / 3% / 8% 로 갈림 |
| 쓰임 | "문제를 발견하는" 장면 | "선택지를 비교하는" 장면 |

DEMO 하나로는 시나리오 비교 표가 전부 같은 값이라 데모가 되지 않는다.
발표에서는 두 인물을 이어서 보여주는 구성이 필요하다.

## LLM 연결

`.env` 한 줄로 프로바이더를 바꾼다. 키가 없으면 자동으로 mock 이 되고,
설정이 잘못돼도 앱은 죽지 않고 mock 으로 떨어진다.

```
FINAGENT_LLM_PROVIDER=anthropic   # anthropic | openai | mock (비우면 자동)
ANTHROPIC_API_KEY=sk-ant-...
```

연결 확인: `python scripts/smoke_llm.py`

**구독은 API 사용권이 아니다.** Claude Max 도 ChatGPT Plus 도 API 결제는 별도다
(console.anthropic.com / platform.openai.com). OpenAI 는 모델 ID 라인업이 자주
바뀌므로 기본값을 두지 않았다 — `OPENAI_MODEL` 을 직접 지정해야 한다.

### LLM 이 숫자를 지어내지 못하게 하는 두 겹의 방어

1. **사전** — 프롬프트에 계산 결과를 사실 목록으로 넣고 그 안의 숫자만 쓰라고 지시
2. **사후** — 생성된 문장의 모든 숫자가 사실 목록에 있는지 기계적으로 검사
   (`agents/explain.py` 의 `verify_numbers`)

2번이 핵심이다. 프롬프트 지시는 지켜지지 않을 수 있지만 검사는 확실하다.
검증에 걸린 숫자는 화면에 경고로 표시된다. 기획서 ⑧ "AI 금융정보 신뢰 검증"을
가장 값싸고 확실하게 구현한 형태다.

## 금융사기 탐지 (기능 ⑦)

세 겹으로 본다:

1. **규칙** (`data/fraud_rules.yaml`) — 레드플래그 9종. LLM 없이 동작하고,
   **어떤 표현이 걸렸는지 그대로 보여준다.** 근거를 댈 수 없는 경고는
   시니어 사용자에게 무의미하다.
2. **정책 대조** (`data/policy_facts.yaml`) — "제도가 바뀌었으니 갈아타라"는 주장을
   공식 팩트시트와 맞춘다. **발표 / 입법예고 / 국회통과 / 공포 / 시행**을 구분하는
   것이 기획서의 핵심 차별점이다. 뉴스는 이걸 구분하지 않는다.
3. **프로필 연결** — "고객님은 ISA에 5,000만원을 보유하고 계십니다"처럼
   실제 자산과 엮는다. 보유하지 않은 상품을 근거로 든 권유는 그 자체가 신호다.

측정된 동작 (기획서 예시 사기 문자):

| | 결과 |
|---|---|
| 사기 문자 | 위험 · 신호 6개 검출 (원금보장+고수익, 비현실 수익률, 재촉, 비공식 채널, 제도 빙자, 비밀 유지) |
| 정상 은행 안내 | 낮음 · **오탐 0** ("연 3.2%"는 정상 범위로 통과) |

정밀도가 재현율만큼 중요하다. "맨날 위험하다고만 한다"고 느끼면 사용자는
경고를 무시하게 되고, 그때부터 이 기능은 없는 것과 같다.

⚠️ `data/policy_facts.yaml` 은 **예시 데이터**다. 발표 전에 원문으로 최신화할 것.

## Supervisor 라우팅

목적지가 둘 이상이 된 시점(사기 탐지 추가)에 만들었다. **규칙이 먼저, LLM 은
애매할 때만.** 붙여넣은 사기 메시지는 길고 광고성 표현이 있어 구조적으로
알아볼 수 있으므로 LLM 을 부를 이유가 없다 — 빠르고, 공짜고, 왜 그렇게
분류했는지 설명된다. 분류에 실패해도 기본 경로로 보내 대화가 끊기지 않는다.

## 웹 (W6)

```bash
uvicorn web.api:app --host 0.0.0.0 --port 8000
```

`core/` 와 `agents/` 는 **한 줄도 고치지 않았다.** W1 에서 "core 는 LLM 도 UI 도
모른다"고 정한 것의 배당금이다. `web/api.py` 는 그것들을 HTTP 로 감싸는 얇은
어댑터일 뿐이고, Streamlit 앱도 그대로 남아 있다.

### 빌드 도구를 쓰지 않은 이유

프런트엔드는 순수 HTML/CSS/JS 다. React + 번들러를 얹으면 HPC 에 node 를 깔고
빌드 단계를 거쳐야 하는데, 그건 발표 당일 실패 지점이 하나 늘어나는 것이다.
차트도 외부 라이브러리 없이 SVG 로 직접 그린다. 오프라인에서도 열린다.

### 시니어 접근성

| 항목 | 구현 |
|---|---|
| 글씨 크기 | 기본 20px. 보통/크게/아주 크게 3단계 (기본값이 이미 커야 한다) |
| 고대비 | 흑백 + 테두리 강조 모드 |
| 음성 | 브라우저 내장 Web Speech API. 외부 서비스도 API 키도 불필요, 속도 0.95배 |
| 터치 영역 | 누르는 것은 최소 48px |
| 색 의존 배제 | 위험도를 색만으로 표시하지 않고 아이콘·글자를 함께 |
| 줄바꿈 | `word-break: keep-all` — 한국어가 낱말 중간에서 끊기지 않게 |
| 키보드 | 포커스 링 항상 표시, 본문 건너뛰기 링크, ARIA 탭·진행률 |

### 알려진 제약

세션은 **메모리 딕셔너리**에 있다. 프로세스를 재시작하면 사라지고 여러 워커로
확장할 수 없다. 데모 범위에서는 충분하지만 실서비스로 가면 Redis/DB 로 옮겨야 한다.
