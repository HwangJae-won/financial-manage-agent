# 이 서비스가 내는 모든 숫자의 출처

화면에 나가는 값이 **어디서 왔고, 확인됐는지, 언제까지 유효한지**를 한 곳에 모았다.
심사·발표에서 "그 숫자 근거가 뭐냐"는 질문에 이 문서 하나로 답한다.

마지막 갱신: 2026-08-14 · 기계로 확인 가능한 것은 `python scripts/check_assumptions.py`

## 읽는 법

숫자는 성격이 네 가지고, **섞으면 안 된다.**

| 표시 | 뜻 | 틀렸을 때 |
|---|---|---|
| **법령** | 법·시행령·고시가 정한 값. 우리가 고를 수 없다 | 계산이 틀린다 |
| **가정** | 우리가 정한 값(수익률·물가 등). 근거는 있지만 선택이다 | 결과가 흔들린다 → 민감도 분석이 이걸 다룬다 |
| **근사** | 제도를 단순화한 값. 정확하지 않다고 화면에 적는다 | 방향은 맞고 크기가 틀린다 |
| **사용자** | 사용자가 입력한 값 | 우리 책임이 아니지만 '가정한 값'으로 표시한다 |

확인 상태는 셋이다.

- ✅ **원문 확인** — 법제처·고시 원문을 직접 받아 대조함
- ⚠️ **미확인** — 값은 있으나 원문 대조 전
- ❌ **낡음** — 원문과 다른 것이 확인됨. 반영 대기

## 2. 우리가 정한 가정

**법이 정한 값이 아니다.** 근거는 있지만 선택이고, 틀릴 수 있다. 그래서
**민감도 분석**(`core/sensitivity.py`)이 이 값들을 흔들어 결과가 얼마나 움직이는지
화면에 미리 띄운다.

| 값 | 코드 | 근거 |
|---|---|---|
| 물가상승률 2.3% | `macro.inflation_rate` | 한국은행 물가안정목표 2.0% + 최근 10년 CPI 평균 반영 |
| 시뮬레이션 종료 95세 | `macro.horizon_age` | 통계청 생명표 60세 기대여명 + 안전마진 |
| 현금성 기대수익률 3.0% | `asset_classes.cash` | 시중은행 1년 정기예금 금리 수준 |
| 채권 3.8% | `asset_classes.bond` | 국고채 3년 + 신용스프레드 근사 |
| 주식 7.0% | `asset_classes.equity` | 글로벌 주식 장기 명목수익률 보수 추정 |
| 변동성 3종 | `volatility` | 위와 같은 출처 |
| 생존자산 12개월 | `asset_map.survival_months` | 비상 현금 통상 기준 |
| 민감도 폭 5종 | `sensitivity.*` | 각 항목 주석 참조 |

## 3. 근사 — 정확하지 않다고 화면에 적는 것

| 값 | 무엇을 단순화했나 | 화면 고지 |
|---|---|---|
| 금융소득 건보료 실효부담률 8% | 제도 구조 대신 평균 부담률 | 참고용 고지 |
| 재산세 과세표준 = 시가 × 0.42 | 공시가격 0.70 × 공정시장가액 0.60 | "추정했습니다" + 경계 근처 경고 |
| 지역가입자 보험료 = **소득분만** | 재산분 점수표 미확보 | **"실제 부담은 이보다 큽니다"** (오차 방향 명시) |
| 의료비 급여 본인부담 비중 60% | 질환별 편차 무시 | "개인의 실제 비율이 아닙니다" |
| 퇴직 전 급여 = 퇴직금 ÷ 근속연수 | 근로자퇴직급여 보장법 제8조 산식 역산 | `assumed_fields` 로 '가정한 값' 표시 |
| 임의계속가입 신청 기한 = 퇴직 +3개월 | 고지서 발행 시점 가정 | "고지서를 받으시면 확인하세요" |
| 몬테카를로 상관계수 0 | 자산군 간 상관 무시 | README 에 "꼬리 위험 과소평가" 명시 |

**계산하지 않기로 한 것** — 근사식을 지어내느니 비워 두는 편이 낫다는 판단.

| 항목 | 이유 |
|---|---|
| 지역가입자 재산분 보험료 | 점수표 미확보 |
| 주택연금 월지급금 | 공사 공시표 미확보 |
| 재취업 소득의 소득세 | 근로·사업·기타소득 체계가 각각 다름 |
| 본인부담상한액 | 시행령 별표가 첨부파일 |
| IRP 과세이연 효과 | 범위 밖. 연금 쪽에 **불리한** 방향이라 보수적 |

## 4. ⚠️ 예시 데이터 — 원문 교체 전

**`data/policy_facts.yaml` 은 예시 데이터다.** 파일 머리에 그렇게 적혀 있다.

| 항목 | 위험도 |
|---|---|
| ISA 세제 개편 파라미터 | **가장 높음.** "연 9만 9,000원이 상한"이라는 이 서비스의 대표 문장이 여기 걸려 있다 |
| 국민연금 개혁 팩트 | 사기 탐지의 "발표 vs 시행" 대조에 쓰인다 |

`checked_at` / `source` / `status` 필드 구조는 이미 제대로 잡혀 있어 **내용만 채우면
된다.** 다만 예시 데이터인 채로 발표하면 가장 아픈 질문을 받는다.

`data/fraud_rules.yaml` 의 레드플래그 9종은 데이터가 아니라 **판단 규칙**이라
출처 확인 대상이 아니다. 다만 오탐/미탐은 테스트로 관리한다.

## 5. 사용자가 넣는 값

우리 책임은 아니지만, 안 물어보고 채운 것은 **'가정한 값'으로 표시**한다
(`UserProfile.assumed_fields`).

| 값 | 어떻게 얻나 |
|---|---|
| 생년월일 · 퇴직 시점 · 월 생활비 | 대화 필수 질문 |
| 퇴직금 · 근속연수 | 한 질문에서 함께 (질문 수를 늘리지 않으려고) |
| 국민연금 예상액 · 가입월수 | 한 질문에서 함께. **모르면 계산하지 않는다** |
| 퇴직 전 월 급여 | 묻지 않고 퇴직금 ÷ 근속연수로 유도 → `assumed_fields` |
| 본인부담상한액 | 화면에서 직접 입력. 모르면 상한제 미반영으로 계산 |
| 재산세 과세표준 | 화면에서 직접 입력. 모르면 시가에서 추정 |

## 6. 갱신 주기

91개 법령 값 중 **매년 바뀌는 것은 5~6개**뿐이고, 바뀌는 달도 정해져 있다.
검색이 아니라 **달력**의 문제다.

| 시점 | 확인할 것 |
|---|---|
| **매년 1월** | 건강보험료율 · 장기요양보험료율 · 최저보험료 · A값 |
| **매년 7월** | 국민연금 기준소득월액 상·하한 |
| 법 개정 시 | 세율표 · 공제 구간 · 감액 구간 · 수급 연령 |

```bash
python scripts/check_assumptions.py          # 유효기간 지난 값 + 원문 대조
python scripts/check_assumptions.py --manual # 사람이 확인할 목록까지
```

**자동 반영은 하지 않는다.** 재산분 점수표를 못 구해 근사식을 만들지 않은
프로젝트에서 긁어온 숫자를 검증 없이 반영하면 앞뒤가 맞지 않는다. 잘못된 자동
갱신은 보이는 낡음보다 나쁘다 — 낡은 값은 "낡았다"는 사실이 참이지만, 잘못
갱신된 값은 "최신이다"라고 거짓말을 한다.

| 건강보험공단 | nhis.or.kr · 1577-1000 | 사람이 확인 |
| 국민연금공단 | nps.or.kr · 1355 | 사람이 확인 |

공식 매뉴얼(open.law.go.kr)의 예시가 `OC=test` 를 쓴다. 다만 **`ID`/`MST`/`LM` 중
무엇을 쓰는지는 문서에 없고 시행착오로 알아냈다** — 법률은 `LM`(법령명), 행정규칙은
검색으로 일련번호를 얻어 `ID`.

파싱할 때 **CDATA 를 먼저 벗기고 태그를 지워야 한다.** 순서를 바꾸면 조문 본문이
통째로 삭제되고, 응답이 짧게 와서 스로틀링으로 오진하기 쉽다.
